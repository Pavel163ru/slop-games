# Slop Games

A static site that bundles several small browser games into one hub page, generated by a build script.

Every game here is an AI-generated experiment: each `game.json` manifest notes the model and the month that produced it.

## Structure

```
slop-games/
  build.mjs            # build script (plain Node, no deps)
  package.json         # npm run build
  <game>/              # each game lives in its own folder
    game.json          # per-game manifest (title, description, type, entry, ...)
    ...                # game source files
  dist/                # generated output (the deployable site)
    index.html         # the generated hub page
    <slug>/            # each game, copied here
  temp/                # local scratch space (not committed)
```

## How it works

`build.mjs` scans every subfolder that contains a `game.json` manifest and:

- **`type: "static"`** — copies the whole game folder into `dist/<slug>/` (ignoring `.git`, `node_modules`, `game.json`, etc.).
- **`type: "build"`** — copies the prebuilt `dist/` of that game into `dist/<slug>/`, then rewrites absolute asset paths (`/assets/`, `href="/"`, `src="/"`) to relative ones so the site works from any subfolder.
- Generates `dist/index.html`, a hub page with a card per game linking to `./<slug>/<entry>`.

All generated paths are **relative**, so the site works on any static host and inside a subfolder.

## Commands

```bash
npm run build     # build dist/
npm run deploy    # upload dist/ to FTP/FTPS (configure .env first)
npx serve dist    # local preview (any static server works)
```

On Windows there are convenience wrappers — double-click them or run from a terminal:

| Script | What it does |
| --- | --- |
| `build.bat` | Builds `dist/` (runs `build.mjs`) |
| `run.bat` | Builds, then serves the site at `http://localhost:4173` via the built-in zero-dependency static server (`serve.mjs`) |
| `deploy.bat` | Uploads `dist/` via FTP/FTPS (runs `deploy.mjs`, pauses so you can read the error if the deploy fails) |

Then deploy the `dist/` folder to any static host.

## Adding a new game

1. Create a folder for the game, e.g. `my-game/`.
2. Add a `game.json` manifest:

```json
{
  "slug": "my-game",
  "title": "My Game",
  "description": "Short description shown on the hub card.",
  "type": "static",
  "entry": "index.html",
  "accent": "#6366f1",
  "order": 10
}
```

- `slug` — folder/URL name (defaults to the folder name).
- `type` — `"static"` (copy the folder) or `"build"` (copy its prebuilt `dist/`).
- `entry` — the HTML file to open (e.g. `index.html` or `game.html`).
- `accent` — card gradient color.
- `order` — sort position on the hub (lower first).
- `model` (optional) — the AI model that generated the game, shown for the record.
- `date` (optional) — generation date, e.g. `"2026-09"`.

3. Run `npm run build`. No changes to `build.mjs` are needed.

## Deploy (FTP / FTPS)

`deploy.mjs` uploads the prebuilt `dist/` to an FTP/FTPS server, incrementally:
it uploads changed files, creates missing directories, and removes files/dirs
that no longer exist locally. It does **not** rebuild — run the build first.

1. Configure credentials (never commit `.env`):

```bash
cp .env.example .env
# edit .env: FTP_HOST, FTP_PORT, FTP_USER, FTP_PASSWORD, FTP_REMOTE_DIR, FTP_SECURE
```

2. Build, then deploy:

```bash
npm run build
npm run deploy
# or just: deploy.bat
```

Settings in `.env`:

| Variable | Meaning |
| --- | --- |
| `FTP_HOST` | Server hostname |
| `FTP_PORT` | Port (default `21`) |
| `FTP_USER` / `FTP_PASSWORD` | Credentials |
| `FTP_REMOTE_DIR` | Remote directory where `dist/` contents go (absolute path) |
| `FTP_SECURE` | `true` for FTPS (explicit TLS), `false` for plain FTP |
| `FTP_REJECT_UNAUTHORIZED` | `false` to allow self-signed certs (default) |

## Notes

- For Vite-based games (`type: "build"`), set `base: './'` in the game's `vite.config.ts` so its prebuilt `dist/` is already relative. The build script also fixes absolute paths on copy as a fallback.
- Build-type games must be prebuilt manually (`npm run build` inside that game) before running the site build — the site builder only copies.
